# 영상 검수표 (시간에 따른 행동·연속성)

정지 이미지가 아니라 **시간에 따른 행동**을 검수한다. 채점은 만든 쪽이 아니라 리뷰어(새 컨텍스트 하위 에이전트 또는 별도 `codex exec` 세션, 지시문은 `<skills>/ai-director-consistency/references/video-reviewer.md` 전문)가 하고, 사람이 핵심 구간을 확인한다(완전 자동 합격은 목표가 아니다). 근거: `docs/2026-11-08-ai-director-review-handoff.md` 6절, 루트 `CLAUDE.md` 1·3·3-1절(그 규칙을 그대로 포함한다. 지우거나 완화하지 않는다).

## 1. 생성 전: 성공 조건 (story.json shot `success_criteria`)
관찰 가능한 문장으로 쓴다. 시간을 과하게 고정하지 말고 **사건 순서와 완료 여부**를 쓴다. 타이밍이 작품상 꼭 필요할 때만 허용 구간을 붙인다.

| 항목 | 예 (S5-3) |
|---|---|
| start | 오른손이 왼쪽 어깨 위에 있다 |
| progress | 손이 팔을 따라 내려간 뒤 팔에서 떨어져 손목이 돌아간다. 멈췄다 다시 출발하지 않는다 |
| complete | 손바닥이 위를 향해 가슴 왼쪽 앞에 멈춘다 |
| continuity | 비가 계속 내리고 어깨·몸이 손을 따라 움직인다. 손은 가운데로 갔다 돌아오지 않는다 |
| identity | 처음과 끝의 얼굴이 같은 사람이다(기준 얼굴과 대조) |
| camera | 고정. 의도하지 않은 줌·팬·내부 컷 없음 |

## 2. 증거 세 가지 (서로 대신하지 않는다)
| 증거 | 만드는 법 | 확인 범위 | 한계 |
|---|---|---|---|
| 프레임 | `scripts/review_video.py`: 0.5초 간격 접촉 시트(시각 표시), 얼굴 처음·25·50·75%·끝 확대 | 외형, 상태, 얼굴·의상·소품 | 프레임 사이 동작을 입증하지 못한다 |
| 수치 | 같은 도구의 `metrics.json`: 밝기, 프레임 차이, 손·얼굴 영역 움직임, 머리 위치 추적, 이음매 | 멈칫, 왕복, 밝기 변화, 튐, 디코딩 오류 | 원인과 연출 의도를 단독으로 판정하지 못한다. 카메라 이동·의도적 정지도 이상값을 만든다 |
| 재생 | 사람(사용자)이 정상 속도로 보거나, 영상 이해 모델이 있으면 그 결과 | 순서, 접촉, 자연스러움, 내부 컷, 소리 | 모델 샘플링이 짧은 결함을 놓칠 수 있다 |

- **정지 프레임과 수치만으로 동작을 합격시키지 않는다.** 재생 확인이 없으면 동작은 "미확인"이다.
- 보고할 때 "프레임으로 본 것", "숫자로 잰 것", "재생으로 본 것"을 나눠 쓴다. "경로를 따라갔다"(수치)와 "자연스럽다"(재생)는 다른 판단이다.

## 3. 검사 순서
1. **기술 검사:** 디코딩 오류, 검은·정지 프레임, 프레임 수, 길이.
2. **전체 흐름:** 0.5초 간격 접촉 시트로 성공 조건의 시작→진행→완료가 순서대로 있는지.
3. **자동 후보 확인:** `metrics.json`의 flags(freeze, direction_reversal, brightness_drift, spike, seam)를 하나씩 열어 본다. 후보는 판정이 아니다.
4. **핵심·의심 구간 정밀 검사:** 접촉·전달·뒤집기 같은 핵심 행동과 후보 구간을 3프레임 간격으로 다시 뽑아 보고, 얼굴·손·소품을 확대한다.
5. **정체성:** 얼굴 스트립을 기준 얼굴과 비교한다(턱, 코, 머리카락 흐름).
6. **샷 내부 결함:** 얼굴 변화, 소품 복제·소실, 발 미끄러짐, 접촉 오류, 깜빡임, 내부 컷, 과장 효과(물 튐, 반짝임), 비가 멈춤, 몸이 굳음, 끝 몇 프레임의 끌림·밝아짐.
7. **편집점:** 실제 사용 구간(`source_in/out`)의 끝과 다음 컷의 시작, 경계 전후 움직임을 비교한다: 손에 든 것, 행동 단계, 인물 시선의 대상·높이·축, 관객 관심점의 인계, 이동 방향, 밝기, 움직이는 부위의 속도(멈칫). `../../ai-director-cinematography/references/eyeline-continuity.md`의 연결표로 인물 시선과 관객 시선을 따로 기록한다. 실제 렌더 경계와 speed/전환이 적용된 재생을 본다. 의도적 단절·생략·장소 전환은 이유와 재정향 단서를 적고 보존한다. 잠긴 영상은 진단과 허용된 조치만 한다.
8. **음향(있으면):** 대사 잘림, 음량 급변, 립싱크, 불필요한 무음. 최종 믹스는 `ai-director-edit/references/sound-rubric.md`로 따로 검수한다.
9. **립싱크 컷 입 확대 검사** (말하는 프레임을 원본·립싱크본 나란히, 입 중심으로 잘라 본다. 사용자 지적 2026-11-09, 「마지막 손님」):
   - **입속이 너무 검다:** 벌린 입 안쪽이 검은 틈으로 보이면 실패. 잣대 = 입 안쪽 가장 어두운 10% 밝기 / 볼 밝기가 기준 결과(sync.so) 수준 0.19 근처. 보정 전 S3-5는 0.07이었다.
   - **입술 경계가 뭉개진다:** 원본보다 입술 윤곽(붉은 입술과 피부의 경계)이 흐리면 실패. 잣대 = 입술 바깥 윤곽점의 밝기 기울기가 원본과 같은 수준. 입 주변 전체의 질감 선명도로 재면 피부 노이즈 때문에 못 잡는다(S4-5).
   - **말하지 않는 구간의 입:** 대사 사이·뒤에 원본과 다른 오므린 입, 어두운 틈이 남으면 실패. 대사 구간만 립싱크 프레임을 쓴다.
   - **말할 이유 없는 입 벌림:** 대사 없는 컷에서 입이 벌어지면 실패(S4-6). 다문 입 프레임으로 고정한다.
   - **얼굴 인식률:** 립싱크 모델 로그의 얼굴 인식 프레임 비율이 절반 미만이면(옆모습·고개 숙임, S3-7 12/97, S4-7 3/96) 결과를 쓰지 않는다. 대사 위치를 입이 안 보이는 컷으로 옮기는 것을 먼저 검토한다.

## 4. 판정 (총점 없음)
- **합격(pass):** 성공 조건을 모두 충족했고 필요한 검사(재생 포함)를 마쳤다.
- **수정 필요(revise):** 결함을 확인했고 수정 대상이 분명하다.
- **보류(hold):** 가림, 해상도, 분석 수단 부족 등으로 확인하지 못했다.
- 얼굴 바뀜이나 행동 실패를 색감·구도의 장점으로 상쇄하지 않는다. 필수 조건은 하나씩 통과해야 한다.

## 5. 결함 기록 형식 (story.json version `review.defects`)
```
00:02.10–00:02.60  관찰: 손이 가슴 앞에서 멈췄다가 다시 움직임(손 영역 움직임 0.7, 앞뒤 2~5)
                   영향: 동작이 끊겨 보임
                   조치: [재생성] 한 테이크로 / [트림] / [부분 수정 VACE] / [후보정]
```
조치는 가장 작은 수단부터: 트림 → 후보정(밝기·색) → 부분 수정 → 재생성.

## 6. 버전·편집과의 연결
- `review`는 미디어 파일의 sha1과 사용 구간(`range_ms`)에 묶는다. 파일이나 구간, 인접 컷이 바뀌면 다시 검수한다. 샷 내부 검수와 편집점 검수의 무효화는 따로 본다(구간만 바뀌면 편집점만 다시).
- **활성 버전은 review.status가 pass일 때만 지정한다.** 판정 보류·미검수 버전은 내보내기에서 막는다(`validate_story.py --stage export`).
- 편집 단계에서는 실제 트림과 연결로 편집점을 다시 검수한다.
- **리뷰어가 쓰는 정확한 필드** (스키마: `ai-director/references/story-schema.md`):
  - 버전 `review`: `status`, `media_sha1`(실제 파일 sha1), `range_ms`([in,out] 정수), `scope`("playback" 포함), `reviewer`, `playback_by`("user" | "model:<이름>", 실제로 재생해서 본 주체), `date`, `criteria`(shot `success_criteria`의 키마다 "met" | "not_met" | "unverified"; export는 전부 "met"이어야 통과). 재생하지 않았으면 `scope`에 playback을 넣지 않고 pass를 쓰지 않는다.
  - 타임라인 `edit_point_reviews[]`: 메인 트랙의 연속한 클립 쌍마다 `a`/`b`({clip_id, version_id, media_sha1, source_in_ms, source_out_ms, speed}), `transition`({type,duration_ms} | null), `status`, `reviewer`, `playback_by`, `date`. 값은 현재 타임라인과 한 글자도 다르면 안 된다. 속도·전환·트림·버전·인접 클립이 바뀌면 그 편집점은 다시 검수한다.
  - 이음매 증거는 `review_video.py <clip> --range <in> <out> --prev <앞 컷> --prev-range <in> <out> --next <뒤 컷> --next-range <in> <out>`로 만든다. 범위는 타임라인 클립의 `source_in_ms/source_out_ms`를 그대로 쓴다. 안 주면 원본 파일 전체의 끝/처음이 쓰여 실제 편집점과 다를 수 있다. `metrics.json`의 `flags.seam.*.a/.b`에 원본 파일, 사용 구간, 분석한 경계 시각이 남는다. 재생 속도(speed)는 도구가 보정하지 않으므로 속도가 1이 아니면 재생으로 직접 본다.
  - `range_ms`를 넓히거나 사용 구간이 검수 범위를 벗어나면(검증기가 `re-review` 오류로 막는다) 그 구간에 핵심 행동이 남아 있는지는 사람의 판단이므로, 편집점만이 아니라 성공 조건 전체를 포함한 샷 재검수를 한다.
