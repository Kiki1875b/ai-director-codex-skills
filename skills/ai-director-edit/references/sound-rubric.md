# 사운드 평가표 (믹스 검수)

최종 믹스를 사용자에게 보내기 전에 항목마다 측정하거나 프레임으로 확인하고, 수치와 함께 보고한다.
근거: 「마지막 손님」 2026-11-09. Gemini(AI Studio, 영상+소리) 검수 22건 중 측정으로 확인된 지적과, 사용자가 "조잡하다"고 평가한 원인.

## 1. 효과음이 들리는가 (가장 흔한 실패)
- **잣대:** 효과음 순간(가장 큰 0.1초)과 그 순간의 배경(빗소리 등 앰비언스+음악)의 차이.
  - 접촉음(잔, 구슬, 스위치, 발소리): **+4dB**
  - 잔잔한 폴리(행주, 종이, 천, 비닐, 마시기, 따르기): **+2dB**
  - 연출용 효과(구슬 빛 등): 최대 **+6dB** (튀면 내린다)
  - 멀어지는 인물의 발소리는 거리만큼 줄인다(예: +2 → -6dB).
- **실패 사례:** 효과음 14개가 배경보다 12~44dB 작았다. 파일은 있었지만 Gemini는 "효과음이 없다"고 들었다. **깔려 있어도 안 들리면 없는 것이다.**
- 효과음 피크는 대사 피크보다 6dB 아래로 둔다. 짧은 소리 하나가 전체 음량을 끌어내리면 안 된다(마시는 소리 +21dB 때 전체 -29.8 LUFS).
- 도구: `python <skills>/ai-director-edit/scripts/sound/fx_levels.py <큐 시트> stories/<slug>/edit/mix/<이름> <새 큐 시트> [--taper <시작초> <끝초> <시작dB> <끝dB>]`(멀어지는 발소리는 `--taper`, 예: 「마지막 손님」 S5-6 `--taper 163 171 2 -6`)

## 2. 효과음이 화면 동작과 맞는가
- 큐마다 앞뒤 0.5초를 10fps 프레임 띠로 보고 접촉 순간(손이 닿는 프레임)에 맞춘다. 화면 전체 움직임량만으로 판정하지 않는다.
- **화면에 없는 동작의 소리는 뺀다.** 실패 사례: 와이드 컷에서 서 있기만 하는데 잔 소리와 물 따르는 소리가 났다(S2-5). 잔을 들고만 있는데 내려놓는 소리가 났다(S3-8).
- **보이는 동작에는 소리가 있어야 한다.** 비닐 커튼, 마시기, 따르기, 발소리, 눈 색이 바뀌는 연출 순간 같은 경우다.
- 재질이 화면과 맞아야 한다. 법랑 컵과 스테인리스 바 장면에 나무 바 위의 머그 소리를 쓰지 않는다.
- 발소리는 걸음에 맞춘다. 일정 간격으로 깔지 않는다. 걸음 간격은 엉덩이가 가장 낮은 순간(디딘 직후)으로 잰다.
- 대사에 묶인 효과(대사 직전에 끊기는 역재생 스웰 등)는 대사를 옮기면 같이 옮긴다.

## 3. 갑자기 끊기거나 튀는 소리
- 잘라 쓴 효과음은 소스가 40dB 줄어들 때까지, 또는 다음 소리가 시작되기 직전까지 울리게 둔다. 페이드는 0.12초 이상. 도구: `python <skills>/ai-director-edit/scripts/sound/cue_tails.py <큐 시트> <새 큐 시트> [--keep-hard <초...>]`
- 장소가 바뀌는 컷에서 나가는 배경음은 컷 뒤로 0.8초 꼬리를 남긴다(L-cut).
- 생성 음악은 지정 길이보다 일찍 끝나는 경우가 많다. 페이드는 실제 음이 끝나는 지점 안에서 건다.
- 감지 기준: 100ms 동안 지속된 소리가 30ms 안에 18dB 이상 떨어지는 곳. 짧은 타격음의 자연 감쇠는 제외한다.
- 의도한 하드컷과 정적은 목록으로 따로 적고 보존한다(예: S4-9 완전한 정적).

## 4. 배경음 변화가 화면 사건과 같은 순간인가
- 커튼이 열리는 순간에 바깥 빗소리가 커진다. 그보다 먼저 커지면 실패다(S4-12: 1초 먼저 커짐).
- 정적 뒤에 대사가 나오면 대사보다 먼저 공간 소리(룸톤)가 돌아와 있어야 한다. 목소리만 마르게 뜨면 실패다(S4-11).

## 5. 대사가 공간에 녹아드는가 (공간감)
- 같은 장소의 대사는 **같은 방 잔향**을 쓰고, 컷 크기로 거리만 바꾼다. 컷마다 제각각이면 실패다.

  | 컷 | 잔향 / 초기 반사 (작은 천막 기준) |
  |---|---|
  | 클로즈업 | -13 / -17dB |
  | 미디엄 | -11 / -15dB |
  | 와이드 | -7 / -10dB, 고음 줄임 |
  | 같은 공간의 화면 밖 | -10 / -14dB |
  | 내레이션·독백 | 잔향 없음, 가깝게 |

- **실패 사례:** 클로즈업 대사의 잔향이 -20dB여서 "스튜디오 녹음처럼 공간과 분리된다"는 지적을 받았다(S2-5, S4-11).
- 대사는 버스 컴프레서(3:1)로 크기를 고르게 하고, 순간 피크를 깎아 대사가 묻히거나 튀지 않게 한다.

## 6. 대사와 화면 속 입
- 입이 보이는 인물이 입을 다문 채 대사가 나오면 실패다. 해결 순서:
  1. 입이 열린 순간에 대사를 맞춘다.
  2. 립싱크한다(`ai-director-shot-gen/references/lipsync.md`, 사용자 요청 시만).
  3. 대사를 입이 안 보이는 컷으로 옮긴다.
- 대사 안의 긴 쉼 때문에 대사가 다음 컷(입을 다문 인물)까지 밀리지 않게 한다(S3-9).
- 립싱크 컷의 입 품질은 `<skills>/ai-director-consistency/references/video-rubric.md` 9번으로 본다.
- 측정 도구: `python <skills>/ai-director-edit/scripts/sound/audit_sync.py <그림 mp4> --story stories/<slug> --json <결과.json>`(대사별 입-소리 상관과 시간 차). 입이 열리는 순간에 대사 시작을 맞추는 것은 `mouth_sync.py --story stories/<slug> [--line <클립>=<컷>:left|right|largest]`(보고만, `--apply`로 story.json에 씀).

## 7. 음악
- 대사 구간에서 음악은 -10dB(느린 복귀 1.2초), 배경음은 -8dB로 덕킹한다.
- 음악이 대사를 덮지 않는다. 음악 없는 구간(재회, 정적, 도입)을 남긴다.
- 곡이 컷과 상관없이 갑자기 들어오거나 나가지 않는다(3절).

## 8. 최종 음량
- 통합 -14 LUFS 근처, 트루피크 -1 dBTP 이하.
- 2dB 넘게 모자라면 피크를 만드는 소리를 먼저 찾는다(대사 피크, 짧은 효과음).

## 자동 검사 도구
`python <skills>/ai-director-edit/scripts/sound/sound_audit.py --cues <큐 시트> --stems stories/<slug>/edit/mix/<이름> --mix <믹스 wav> [--story stories/<slug>] --sync <audit_sync.py --json 결과> --events <화면 사건 목록> --hard <의도한 하드컷 초...> --offscreen <일부러 화면 밖인 대사 id...> [--skip-shots <6번에서 뺄 컷 id 접두어...>]`
- 1, 1b, 3, 4, 5, 6, 8번을 수치로 판정한다. 2번(화면에 없는 동작의 소리, 재질)은 프레임 띠로 직접 본다.
- 6번에서 대사가 자기 컷이 아닌 컷 위에 흐르면 "보이는 얼굴이 듣는 사람인가?", 얼굴을 못 찾으면 "직접 확인"으로 따로 나온다. 이 목록은 반드시 눈으로 본다.
- **검증(2026-11-09, 문제가 있던 옛 믹스 v3 vs 수정본 v9):** 옛 믹스의 알려진 문제를 다음과 같이 잡았다.
  - 안 들리는 효과음 35건, 너무 큰 구슬 효과 2건
  - 끊김 13건(음악 끝 2, 장소 전환 3, 대사 중간 역재생 스웰 1 포함)
  - S4-12 빗소리가 0.7초 일찍 커짐
  - 마른 대사 7줄
  - S4-2 입-소리 시간 차(-8프레임)
  - S3-9② 대사가 S4-1 위에 흐름("듣는 사람인가?" 목록)
  - 놓친 것: S4-7(와이드 옆모습이라 얼굴을 못 찾음, "직접 확인" 목록으로만 나옴), S2-5의 화면에 없는 따르는 소리(2번, 수동 항목)
  - 오탐으로 고친 것: 듣는 사람 얼굴, 일부러 마르게 한 화면 밖 독백, 사용자가 맞다고 한 S6-3 시간 차(-5프레임). 시간 차 허용 범위는 -6~+10프레임(30fps)이다.
- 같은 도구가 수정 과정의 회귀도 잡았다. "대사 구간만 립싱크"(`ai-director-shot-gen/scripts/lipsync_legacy/speech_only.py`)가 S6-4의 입-소리 일치를 0.60에서 0.26으로, S2-3을 0.80에서 0.50으로 떨어뜨렸다. 원본 입이 쉼 동안에도 움직이는 컷이었다. **처리 전후로 `lipsync_eval.py`의 sync를 비교하고, 떨어지면 쓰지 않는다.**

## 9. 외부 "귀" 모델로 검수할 때 (Gemini 등)
- 영상과 소리를 함께 넣고, 컷 시간표, 의도한 연출(정적, 내레이션), 항목, 표 형식(시간 | 컷 | 항목 | 문제 | 고칠 방법 | 확신)을 준다.
- 지적은 **그대로 믿지 않고 측정으로 확인한다.**
  - "효과음이 없다"는 대부분 **너무 작다**였다(1절).
  - "입이 닫혀 있다"는 립싱크된 클로즈업에서 틀렸다. 영상을 1초에 1장 정도만 보고, 업로드용으로 화질을 낮춘 탓으로 보인다. 입 판정은 프레임 확대와 측정으로 한다.
- 업로드는 10MB 이하(640p, 영상 230kbps, 소리 96kbps)로 만든다. 소리 품질은 판정에 충분하다.
